The CLI added the development credentials to any server string without user info. With `auth=none`, that sent credentials the user had explicitly opted out of, and against a kernel without TLS the token request always failed. (part of Cratis/Chronicle#5443)

## Fixed

- A server string with `auth=none` is used as is. No development, stored or login credentials are added to it.
- A server string with `disableTls=true` and no credentials no longer gets the development credentials added. Chronicle serves its token endpoint over TLS only. Stored service-account credentials and login tokens are still added as before.
