`cratis affected run` no longer stops at the first test project that does not build, and builds a project for its own framework when it lacks the requested one.

## Fixed

- Fix `cratis affected run` aborting every project after one whose build failed; the project now fails the run and the others still run (part of Cratis/Workflows#268).
- Fix a test project that targets only one framework failing when `--framework` names another; it is built for the framework it has.
- Fix a merge-time `cratis affected run` losing the maps of every project when one project does not build; the others keep their new maps.
