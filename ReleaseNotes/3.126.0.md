A builder can now run as an always-on user service, and builds with Copilot CLI and other Agent Client Protocol agents get the Screenplay tools.

## Added

- `cratis build service install`, `uninstall` and `status` run a project's build loop as a user service that starts at sign-in and restarts 30 seconds after it stops: a launchd agent on macOS and a systemd user unit on Linux. `install` takes the options of `cratis build run`; the service gets the `PATH` of the installing shell and no credentials. See [cratis build service](https://github.com/Cratis/cli/blob/main/Documentation/reference/build.md#service). (part of Cratis/StudioIssues#1352)

## Fixed

- `cratis build run` no longer refuses a kit installed with `cratis build init` with "/scaffold/path: ./scaffold is not in the kit": the installed copy keeps no scaffold, and is now loaded as installed.
- Agents that connect to MCP servers over HTTP, such as Copilot CLI, now get the Screenplay tools in a build session: local tools are served to them on a loopback address guarded by a per-session token. Before, Copilot CLI refused the tools and built without checking the model or running the slice's specifications.
- An agent that ends its turn without writing its outcome, as Copilot CLI does when one of its actions is refused, is asked to go on up to twice instead of the build failing at once.
- Claude Code build sessions no longer load the user's own Claude Code settings. A user hook that rewrites shell commands made every command the kit permits fail its permission match, so the agent never built or tested its work; user plugins and the default model no longer change how a slice is built either.
