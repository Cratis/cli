## Changed

- Bundles Stage 4.201.1 (from 4.196.0) and Screenplay 4.247.3 (from 4.240.2): `cratis run` starts `cratis/stage:4.201.1` by default and `cratis render` plans with the same renderer. A reaction can now map `$eventSourceId` into a produced event or a command argument, so models that do this run instead of failing with `STAGE-ESM-013`; the Stage host no longer lists its own `/stage` and `/workbench` endpoints in the OpenAPI document and the Scalar reference.
- `cratis render` admits ESM v1 through v32 (from v30), including typed capture identities.
- Rendered code uses short, idiomatic type names, and the generated application compiles its specifications in Debug instead of a separate specifications project.
- Local public events render through the outbox and inbox instead of being refused with `STAGE-ESM-032`.
