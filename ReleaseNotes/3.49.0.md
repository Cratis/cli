## Added

- `cratis render --scope <Module[.Feature],[.Slice]>` renders only the selected modules, features or slices; the option can be repeated. A renderer refusal (`STAGE-ESM-*`) in an unselected slice no longer blocks the render, while execution-plan errors (`PLAN-*`) anywhere in the model still do until [Cratis/Screenplay#656](https://github.com/Cratis/Screenplay/issues/656) is available (part of #247)
- Scoped renders never delete or overwrite files that belong to other scopes. The ownership manifest records which module, feature and slice each file comes from, and a later full render takes over every file a scoped render produced (part of #247)
- A scoped render is refused before anything is written when a selected slice depends on declarations that are neither selected nor already in the destination (`CLI-RENDER-014` names them and the scope to add), or when the destination still uses the aggregate policy layout, which needs one full render first (part of #247)
- A scoped render into an empty destination includes the application scaffold so the result builds, and the receipt lists the scope, the slices outside it and any orphaned files; `--check` works with `--scope` (part of #247)
