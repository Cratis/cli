## Fixed

- `cratis screenplay mcp` started with `--project-root` or `--project-root-env`, as `cratis ai install` registers it, or with a `.cratis/ai.json` that sets no model root, keeps serving a folder that already holds Screenplay workspace state, so applied identities and interrupted-write recovery are no longer lost when the model lives in a nested folder. When several folders between the project and the model hold state, the one nearest the project is used and the others are reported on standard error; an interrupted write in another of those folders, or workspace metadata that is a link or has the wrong file type, stops startup with a message naming the folder. (#268)
