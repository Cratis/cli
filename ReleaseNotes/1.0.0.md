This is the first release of the Cratis Chronicle CLI — a dedicated command-line tool for inspecting, managing, and operating Chronicle from the terminal.

## Added

### Core experience
- `cratis get-started` — context-aware onboarding command showing active context details, live connectivity status, curated command reference, debugging scenarios, and tips
- Animated ASCII banner and gradient figlet renderer on startup
- First-run detection with guided setup prompt
- Automatic update checker on every invocation
- `cratis version` and `cratis version self-update` — show the current CLI version and self-update in place

### Context management
- Full context lifecycle: create, delete (built-in `default` context protected from deletion), rename (guards against same-name and empty names), set (no-op detection), list, show, path
- `cratis context set-value` — set individual context properties (server, event-store, namespace, auth-type, client-id, client-secret); keys normalised to kebab-case; `client-secret` values masked in output

### Chronicle — server
- `cratis chronicle event-stores list` — list all event stores on the connected server
- `cratis chronicle namespaces list` — list namespaces in the active event store
- `cratis chronicle diagnose` — live diagnostic: connection health, version, and configuration

### Chronicle — events
- `cratis chronicle events get` — retrieve events with filtering by type, sequence range, and partition
- `cratis chronicle events count` — count events matching a filter
- `cratis chronicle events tail` — stream incoming events in real time

### Chronicle — event types
- `cratis chronicle event-types list` — list all registered event types
- `cratis chronicle event-types show` — inspect the full schema of an event type

### Chronicle — observers
- `cratis chronicle observers list` — list observers, optionally filtered by type
- `cratis chronicle observers show` — show detailed state of a single observer
- `cratis chronicle observers replay` — trigger a full replay of an observer
- `cratis chronicle observers replay-partition` — replay a specific partition
- `cratis chronicle observers retry-partition` — retry a failed partition

### Chronicle — failed partitions
- `cratis chronicle failed-partitions list` — list all partitions in a failed state
- `cratis chronicle failed-partitions show` — show failure details and stack trace for a partition

### Chronicle — projections
- `cratis chronicle projections list` — list all registered projections
- `cratis chronicle projections show` — show the full definition of a projection

### Chronicle — read models
- `cratis chronicle read-models list` — list all read models
- `cratis chronicle read-models instances` — list all instances of a read model
- `cratis chronicle read-models get` — retrieve a read model instance by key
- `cratis chronicle read-models occurrences` — show event occurrences for a read model instance
- `cratis chronicle read-models snapshots` — show snapshots for a read model

### Chronicle — jobs
- `cratis chronicle jobs list` — list running and completed jobs
- `cratis chronicle jobs get` — get details of a specific job
- `cratis chronicle jobs stop` — stop a running job
- `cratis chronicle jobs resume` — resume a stopped job

### Chronicle — recommendations
- `cratis chronicle recommendations list` — list active system recommendations
- `cratis chronicle recommendations perform` — execute a recommendation
- `cratis chronicle recommendations ignore` — dismiss a recommendation

### Chronicle — identities and users
- `cratis chronicle identities list` — list all known identities
- `cratis chronicle users add`, `remove`, `list` — manage users on the server

### Chronicle — applications
- `cratis chronicle applications add`, `remove`, `list` — manage registered applications
- `cratis applications rotate-secret` — rotate the client secret for an application

### Chronicle — authentication
- `cratis chronicle auth login` — authenticate using the client credentials flow
- `cratis chronicle auth logout` — clear stored credentials
- `cratis chronicle auth status` — show current authentication state

### Shell completions
- `cratis completions install` — install tab completions for bash, zsh, or fish
- Dynamic completions for context names, event store names, observer IDs, job IDs, and more — resolved live from the connected server

### AI tooling integration
- `cratis init` — detect installed AI coding tools (Claude, Cursor, Copilot, etc.) and generate slash commands and LLM context files so AI agents can operate the CLI natively
- `cratis llm-context` — emit a structured JSON description of the full CLI surface for consumption by language models

### Output and infrastructure
- All commands support `--output json` for machine-readable output
- Rich terminal UI via Spectre.Console with consistent colour conventions (panels, tables, colour, markup)
- Source generator (`Cli.Generators`) auto-registers all `[CliCommand]`-annotated classes at build time — no manual wiring required
- Full integration test suite against a live Chronicle container covering every command group
