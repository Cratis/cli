The CLI renders and runs the domain blueprint samples exactly as authored, and a screen that names a blueprint template that does not exist now stops the render instead of showing a screen with no template.

## Added

- `CLI-RENDER-020`: a `template blueprint <Package> <Template>` reference to a template the approved blueprint's manifest does not list - no such template, a version outside the pin, or a blueprint that is not approved - stops `cratis render`, and `cratis run` before Docker starts, naming the blueprint and the template. The resolution is Scene's own template resolver, run by Stage's render planner over the approved package set.
- A specification that checks a screen naming a template the blueprint does not ship while another one it does ship is accepted.

## Changed

- Bundles Stage 4.132.0 (and the `cratis/stage:4.132.0` image `cratis run` starts), which renders the specifications, one-row summary projections and live collections of the CRM, Ticketing, Approvals, Inventory, HR, Project tracker, Administration and Orders samples without simplifying them (Cratis/Stage#478).
