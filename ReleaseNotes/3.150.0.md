Build and test only what a pull request can reach, using one command in the Cratis CLI.

## Added

- Add `cratis affected select`, which decides which test projects and which tests a change can reach from the project graph and per-project coverage maps, and writes a JSON and Markdown selection report that explains each decision (part of Cratis/Workflows#268).
- Add `cratis affected run`, which runs the selection; with `--mode merge` it runs every test unit in isolation under `dotnet-coverage` or `coverlet` and writes deterministic coverage maps to `.cratis/affected/maps`.
- Add `cratis affected replay`, which replays merged changes against the maps committed before them and reports the median fraction of tests selected and every failure the selection would have missed.
- Add the Affected tests documentation, covering the selection rules, the `.cratis/affected.json` configuration and how a selection reaches the xUnit v3 runner.
