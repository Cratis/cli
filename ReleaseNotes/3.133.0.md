You can now check an extension package before it is published or loaded with `cratis extension verify`.

## Added

- `cratis extension verify [TARGET]` checks a package folder, or a package a registry serves (a catalog short name, an OCI reference or an npm package), and reports every check with a status and exact diagnostics. See https://github.com/Cratis/cli/blob/main/Documentation/reference/extension-verify.md. (part of #576)
- Checks: the contract compiles with no errors or warnings; the manifest has a display name, a description, an icon and stated requirements, and the icon and marketplace images exist, are `png`, `jpg`, `webp` or `svg` by their content and are within the size limits; the package ships what the contract declares and nothing else (a folder lists what its build does not ship in `.extensionignore`); every placeholder is static HTML; the package digest and contract hash match `screenplay.lock`; and the contract is usable by the Screenplay compiler, with `--baseline <FOLDER>` to require a drop-in replacement for the previous release.
- A check that applies but could not run is reported as skipped, never as passed. The frontend (Scene conformance kit) and backend (protocol handshake) checks are skipped for now; `--strict` fails them, and warnings, too.
- Human-readable output by default and `--format json` on request. Exit code `0` when the package is correct, `5` when a check failed, `1` when the target or reference is not found, `2` when a registry is unreachable and `4` when its credentials are refused.
- A package that `cratis extension new` creates from templates that follow the documented template interface passes `cratis extension verify`.
