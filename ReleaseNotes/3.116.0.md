`cratis run` now runs a Screenplay model the way it runs in production: behind AuthProxy when the model declares authentication, with its own Ante when it declares onboarding, configured from the selected environment.

## Added

- `cratis run` starts AuthProxy in front of the Stage when the model has `authentication`, configured from the model's providers and the selected environment, and opens the application through it; the Stage trusts the identity AuthProxy forwards instead of playing a persona (#516)
- `cratis run` starts the application's own Ante in development mode, with a MongoDB and the model's legal terms, when the model has `onboarding`; onboarding emails are written to `.cratis/local/mail` unless the environment names a mail server
- `cratis run` stops before starting any container when the environment lacks keys the model needs, and lists them
- `cratis run` options `--environment`, `--auth-port`, `--lobby-port`, `--authproxy-tag` and `--ante-tag`
- `cratis config --missing <model>` reads the keys a `.play` file or folder needs and lists those the environment lacks
- `cratis render` renders a model's `authentication` and `onboarding`: the AuthProxy, Ante and environment configuration under `.runtime/`, sign-in and persona mapping, onboarding provisioning and the email templates

## Changed

- The CLI bundles Stage 4.211.0 and Screenplay 4.259.0, and `cratis run` uses the `cratis/stage:4.211.0` image by default
