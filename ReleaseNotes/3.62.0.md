## Changed

- `cratis render <PATH>` now renders with the model root's persisted identities when `.screenplay/identities.json` exists, so generated event and type ids match the ones Studio and the Screenplay MCP use. **Generated output changes for roots with persisted identities**: earlier releases ignored those identities and rendered temporary ones, which diverged from the rest of the toolchain. To see the change, render the same root with the previous CLI and with this one into two folders and diff them. Roots without persisted identities render exactly as before. Existing destinations still face the stored event type id check (`CLI-RENDER-016`). See [Render options](https://github.com/Cratis/cli/blob/main/Documentation/reference/screenplay.md). (#361)
- For a root with persisted identities, `--name` must equal the saved application name; a different name is refused with `CLI-RENDER-018`. If the root cannot be opened (for example a pending operation or conflicting identities), render refuses with `CLI-RENDER-017` and the reason instead of falling back to temporary identities. (#361)
- Release-baseline warnings for PATH input now come from the same opened workspace the render uses, so their model revision always matches the rendered model. (#361)
- The CLI bundles Stage 4.99.0.
