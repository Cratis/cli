Build slices from Cratis Studio with the coding agent or generator of your choice, and pull model context for agents from the terminal.

## Added

- `cratis build connect`, `run`, `once` and `status`: a builder host for Cratis Studio. It registers the machine with a short code, agrees the protocol version, claims slices, keeps the claim alive, runs the kit's verification commands (a failing command reports the slice as failed, never built), commits on the kit's branch and reports the outcome. Builds run with Claude Code natively, with Codex, Gemini CLI, Cursor, GitHub Copilot CLI or OpenCode over the Agent Client Protocol, or with any generator through `--exec`. Credentials stay in the operating system's credential store and are never written into prompts, orders, outcomes or logs. (#560)
- `cratis build init --kit <name|git url>` installs a build kit from Studio (checksum verified) or from Git (`#<branch, tag or commit>`, `--kit-folder`), scaffolds an empty project or prepares an existing codebase whose conventions the first build learns, writes the kit's instructions and skills where the chosen agent reads them, and records the installation in `.cratis/build/kit.json`. `cratis build kit validate` checks a kit for authors. (#561)
- `cratis build run --modeling --board <board> --agent <agent>` connects a local coding agent to a Studio board: it shows as connected, people hand it work by mentioning it in the board chat, and it answers there. It proposes changes for a person to confirm, or acts at once with `--unattended`; what it changes on the board is attributed to it. (#562)
- `cratis studio fetch --context <slice|feature|eventModel|domain> --id <id> --format markdown|json|yaml|toon [--out <path>]` fetches the context of part of a model for an AI agent or a pipeline, with the same Studio connection as `cratis build`. (#563)
