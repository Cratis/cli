`cratis build run` now runs the same builder Studio runs in the cloud, locally or in Docker, with model calls made through Studio.

## Added

- `--level screenplay`, `code`, `code-ai` and `ai` run the packaged Cratis builder at the four modes Studio offers: Screenplay only, static code, static code refined by AI and AI only. `--target axon` renders for Axon Framework instead of Cratis.
- At `code-ai` the model is rendered deterministically and an agent then implements the behavior the model describes on top of the generated code. At `ai` the agent implements the slices from the model without rendering. Every agent prompt ends with *Instructions from the model*: the slices' descriptions from the order's `context.hints`, the specifications to meet and the feedback people left.
- `--docker` runs the builder in a packaged image with the project mounted, and `--image` chooses the image. A builder in a container reads its connection from `CRATIS_STUDIO_URL`, `CRATIS_STUDIO_ORGANIZATION`, `CRATIS_BUILDER_ID` and `CRATIS_BUILDER_TOKEN`.
- `--ai studio` sends an agent's model calls through Studio's AI gateway, on the organization's providers, over a loopback bridge that speaks the OpenAI and Anthropic APIs. Generators get `STUDIO_AI_URL` and `STUDIO_AI_TOKEN`.
- A Dockerfile and a manual workflow for the packaged builder image.
- Documentation for running the Cratis and Axon builders locally at every level.

## Changed

- The builder speaks builder protocol versions 1 and 2.
