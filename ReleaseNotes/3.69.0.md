Part of Cratis/Stage#457 (domain blueprints in `cratis render` / `cratis run`).

## Added
- A spec checks a `ui profile` naming `Cratis.Blueprint.Crm`: refused with `CLI-RENDER-007` until approved, accepted once approved with the manifest the package publishes (with its `blueprint` and `sampleData` members).

## Changed
- The CLI bundles Stage 4.125.0, whose catalog ships `PrimeReact` and `Cratis.Blueprint.Default` and whose live Stage and generated React application load the templates of approved domain blueprints; `cratis run` starts `cratis/stage:4.125.0` by default. Scene 4.53.1 accepts a blueprint manifest in the approved package set.
- Two scope specs that used a generated-concept collision as their example of a construct Stage refuses now use an interval reaction (`STAGE-ESM-024`), since Stage 4.121 onward renders the former.

## Fixed
- `cratis render --package-set` of an application that uses a domain blueprint no longer fails with `CLI-RENDER-009`/`CLI-RENDER-002`.
