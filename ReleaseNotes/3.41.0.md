`cratis render` now refuses a UI profile it cannot honor instead of publishing a fallback. An application it renders can now be recovered with `cratis screenplay generate`.

## Added

- `cratis render` resolves every `ui profile` against the packages the bundled `cratis` target renders (`core`, `scene.web` and `Cratis.Components`) before it publishes anything. A profile it cannot honor stops the render: nothing is published, and managed artifacts from an earlier render stay as they were. The new diagnostics are `CLI-RENDER-007` (unknown package), `CLI-RENDER-008` (missing layout), `CLI-RENDER-009` (packages that cannot be combined, such as an incompatible theme or a missing dependency) and `CLI-RENDER-010` (undeclared theme). See [UI profile resolution](https://github.com/Cratis/cli/blob/main/Documentation/reference/screenplay.md#ui-profile-resolution). (part of #284)

## Changed

- A profile naming an unknown package or a missing layout used to publish every artifact and exit 0. It now fails. Fix the profile if a render that used to succeed now reports `CLI-RENDER-007` through `CLI-RENDER-010`. (part of #284)
- `CLI0017` now names the reason a source path was refused and, when one path is responsible, that path, relative to the solution or project you read.
- The bundled Arc source adapter is now 22.54.0.
- The CLI now uses Stage 4.51.3, and `cratis run` starts `cratis/stage:4.51.3` by default.

## Fixed

- `cratis screenplay generate` no longer refuses a project that references a package adding compile items from inside its own folder, such as `Microsoft.NET.Test.Sdk`. Every application `cratis render` produces references it, so recovery always stopped with `CLI0017`. (part of #284)
- Recovering a rendered application now declares the read models its queries and projections return, so the recovered model binds. (part of #284)
