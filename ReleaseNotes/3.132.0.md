You can now create an extension package with one command: `cratis extension new`.

## Added

- `cratis extension new` creates a full extension (an OCI artifact) or a frontend-only component package from the `Cratis.Templates.Extensions` templates. A full extension takes a `--backend` (`csharp`, `kotlin`, `go`, `typescript` or `none`) and a `--frontend` (`react`, `mount`, `screenplay` or `none`); a frontend-only package takes a `--component` (`react` or `mount`). Every package gets a `contract.play` with its manifest, a placeholder icon and image, a static HTML placeholder per frontend component, a sample ability or component with specs, a README and the build and publish scripts. See https://github.com/Cratis/cli/blob/main/Documentation/reference/extension-new.md. (part of #575)
- An interactive wizard that asks only what the flags did not answer. The wizard and the flags build the same request and are held to the same rules, so they create the same package. `--no-prompts` never asks; `--dry-run` lists the files; `--format json` reports them.
- `--template-path`, `--package` and `--version` choose where the templates come from. The CLI fails with exit code 2 and names the symbol when a template does not offer a choice the request needs.
- The template interface, the names of the templates and the symbols the CLI passes to them, is documented so the templates can be built against it.
