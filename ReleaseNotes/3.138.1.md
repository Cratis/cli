## Fixed

- `cratis env change-secrets-provider` now cleans up correctly when secrets move between two stores of the same provider: moving between two Azure Key Vaults, or between HashiCorp Vault mounts or namespaces on the same server, removes the old entries; when the old and new stores might be the same (a vault alias, or a different Vault server address), the old entries are kept and a warning names each one, so a move can never delete the secrets it just wrote. The JSON output reports how many entries were removed and any warnings (#538)
