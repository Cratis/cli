## Added

- `cratis chronicle auth status` shows the server your login belongs to and whether the selected server matches it, with `tokenServer` and `loginMatchesServer` in JSON output (#198)
- Commands print a notice when your stored login belongs to another server, so you know they are running without it, instead of reporting this only with `--debug` (#198)

## Changed

- `cratis chronicle login` no longer accepts a root certificate (PEM or DER) as `certificatePath`; the setting names a client certificate, as it already did for every other command (#198)

## Fixed

- `cratis chronicle login` honours the connection string's `certificatePath` the same way every other command does: it presents it as a PKCS#12 client certificate, with or without a password, so login works against servers that require client certificates and against publicly trusted servers when a client certificate is configured (#198)
- `cratis chronicle login` reports a clear error when the configured client certificate is missing, invalid or has the wrong password (#198)
- A stored login made against an IPv6 server address is recognised when the same server is written differently, such as `[::1]` and `[0:0:0:0:0:0:0:1]` (#198)
