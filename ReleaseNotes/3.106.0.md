## Added

- `cratis render --strict` fails a render that Stage reports as degraded. The safe artifacts, removals and reports, including the completeness report, are still published, and the command then exits with the new exit code 9 (`strict_unaccepted`). Without `--strict`, a degraded render still publishes and succeeds. A refused render still exits 5 whether or not `--strict` is set. Real errors (1, 5, 10) take precedence over 9, which takes precedence over pending changes (6). With `--check`, nothing is written and a strict failure takes precedence over drift. See [Strict rendering](https://github.com/Cratis/cli/blob/main/Documentation/reference/screenplay.md#strict-rendering). (#468)
