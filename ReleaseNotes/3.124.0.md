The CLI now bundles Screenplay 6.0.0 and Stage 5.0.0, so `cratis` compiles models with slots and outlets and renders and runs them with Scene 5. Models written for Screenplay 5 must be migrated once with `screenplay migrate <model root> --from 5 --to 6`.

## Changed

- The CLI bundles Screenplay 6.0.0, including its MCP server, which now offers the `migrate` tool. Component `outlet` is now `slot`, `navigation topbar|sidebar` is now `outlet <name> of navigation`, and a module's `navigation sidebar extends` is now `outlet sidebar extends`. The old forms are refused with a message naming the migration, so run `screenplay migrate <model root> --from 5 --to 6` once before editing a model written for Screenplay 5. See [Migrating a model](https://github.com/Cratis/Screenplay/blob/main/Documentation/screenplay/migration.md).
- `cratis screenplay validate` reports a State Change command nothing issues (`PLAY0533`) as a warning by default, so a model generated from backend code with `cratis screenplay generate` now validates with one warning per command.
- The CLI bundles Stage 5.0.0, built on Screenplay 6.0.0 and Scene 5.1.0, and `cratis run` uses the `cratis/stage:5.0.0` image by default. A screen toolbar renders as Scene outlet buttons, and routed slots keep the selected item, tab and filters in the address.
- `cratis render --target cratis` generates applications on Arc 22.176.0 and Chronicle 19.142.0, and `cratis screenplay generate` uses the Arc source adapter 22.176.0 and Screenplay generation 0.20.0.
