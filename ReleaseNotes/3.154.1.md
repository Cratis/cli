## Changed

- Server addresses that do not identify a single host (DNS SRV, multiple hosts, or addresses with user information) no longer cache tokens on disk; the token is kept in memory for that run only.
- `cratis chronicle logout` removes every cached token for the active context and client, across all destinations.
- The authentication documentation describes where tokens are cached and how they are scoped to their destination.

## Security

- Cached Chronicle OAuth tokens are now bound to the token server and Chronicle server they were issued for, and the CLI only sends a cached token to that same destination. Cache entries from earlier versions, or without a recorded destination, are never sent and are replaced on the next authentication. (#656)
