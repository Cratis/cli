## Added

- `cratis render` writes authored Screenplay `description` text as XML doc comment summaries on generated commands, events, read models, queries and types, and event `documentation` as remarks. Metadata the renderer cannot use, such as text with characters invalid in XML, blocks rendering with `CLI-RENDER-005`. When the documents cannot be read as a Screenplay workspace, for example a file with an upper-case `.PLAY` extension, the model renders without the comments and `CLI-RENDER-006` says why. (#278)

## Changed

- The CLI bundles Stage 4.36.0, and `cratis run` starts the Stage 4.36.0 container, which compiles models with Screenplay 4.81.5.
- `cratis render` admits ESM v5 to v7 and leaves refusals to the renderer, which names the construct it cannot render: reactions, captures, triggers and Automation or Translate slices (`STAGE-ESM-024`), read-model absence assertions (`STAGE-ESM-027`), generated command values (`STAGE-ESM-028`) and command responses (`STAGE-ESM-029`). Policy negation now renders. `CLI-RENDER-004` is reported only for a model newer than ESM v7.
- Rendered policies no longer refuse number or Boolean claim comparisons, which never match, and compare Uuid, Date and DateTime claims only against Screenplay's canonical text, so generated policy code changes for those claims.
- `cratis run` refuses a screen `action` with `when … execute` alternatives (`STAGE-SCENE-ACTION-001`).
