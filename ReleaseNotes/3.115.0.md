`cratis prologue` can now set up and interpret captures of a system made of several services.

## Added

- `cratis prologue start` asks whether the system is made of several services. If it is, the wizard collects each named service with its own SQL Server and PostgreSQL databases, API base path and address, and OpenTelemetry `service.name` values, and writes them under `prologue.services` with one reverse-proxy route and cluster per service. See [Prologue](https://github.com/Cratis/cli/blob/main/Documentation/reference/prologue.md#a-system-made-of-several-services).
- `cratis prologue interpret --service <NAME>` interprets only the captures of one named service. Without it every captured service is interpreted, each into its own module.
- `cratis prologue interpret` reports the interpreted services in its summary panel and as a `services` array in JSON output.

## Changed

- The CLI now bundles Prologue 2.1.0, and `prologue start` prints the `cratis/prologue-extractor:2.1.0` image.
