`cratis --version` always reported `1.0.0.0` regardless of the installed NuGet package version, because `SetApplicationVersion` was reading the 4-part `AssemblyVersion` attribute instead of the semantic `AssemblyInformationalVersion`.

## Fixed

- `--version` flag now reports the correct semantic version by using `VersionCommand.GetCliVersion()` (reads `AssemblyInformationalVersionAttribute`) instead of `Assembly.GetName().Version` (always `1.0.0.0`)
- Publish pipeline now embeds the correct version into the assembly by passing `-p:Version=` to `dotnet build`, ensuring the informational version in the published assembly matches the NuGet package version
