## Summary

`cratis screenplay validate --help` shows its options again, and the command no longer passes when a flag is misspelled.

## Changed

- The `validate` help and the Screenplay reference list every `--check` name (including `personas`, `purposes`, `privilege` and `enum-pinning`) and the exit codes: 0 valid, 1 missing or invalid input or scope, 5 validation failed. (part of #339)

## Fixed

- `cratis screenplay validate --help` printed the description and examples and then failed with a markup error before listing the options; the full help, including `--scope`, `--check`, `--executable` and `--warnings-as-errors`, is shown again. (part of #339)
- `--warnaserror`, the standalone `screenplay` tool's spelling, is accepted as an alias of `--warnings-as-errors`; before, it was silently ignored and a model with warnings passed. Any other unknown option now fails with exit code 5 instead of being ignored. (part of #339)
- An unknown `--check` name fails with exit code 5 and a message listing the valid check names, instead of exit code 255. (part of #339)
