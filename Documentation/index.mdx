  <TabItem label="Homebrew" icon="apple">

  ```bash
  brew tap cratis/cratis
  brew install cratis
  ```

  </TabItem>
  <TabItem label=".NET tool" icon="seti:c-sharp">

  ```bash
  dotnet tool install -g Cratis.Cli
  ```

  </TabItem>
</Tabs>

The .NET tool requires the runtime declared by the current package. Native
release assets and platform coverage vary by release; verify the exact artifact
before installation.

## Connect and inspect

<Steps>
1. Create a named Chronicle connection context.

   ```bash
   cratis context create dev --server chronicle://localhost:35000
   ```

2. Select that context.

   ```bash
   cratis context set dev
   ```

3. Run the documented diagnostic summary.

   ```bash
   cratis chronicle diagnose
   ```
</Steps>

The diagnostic command reports its documented connection, observer,
failed-partition, and recommendation checks. Use command help and the exact CLI
version to inspect the current command and output surface.

## Product relationship

Chronicle Workbench provides a bundled local browser surface for authorized
inspection of Chronicle runtime state and preview of supported projection
behavior. The CLI provides the terminal inspection and diagnosis path around
the same product family.

The CLI also contains separately documented command groups for other Cratis
products. Their presence does not establish those products' maturity, support,
compatibility, or availability.

## Current boundaries

:::caution[Inspection is not authority]
Inspection capability does not imply complete administration or production
mutation authority. Confirm the event store, namespace, target, current state,
and documented operational procedure before a mutation command.
:::

- Ordinary output formats are not an unversioned stable machine contract.
- Command availability does not establish support, an SLA, reliability,
  security, compatibility, or production suitability.
- Connection strings and context files can contain credentials; keep them out
  of source, public issues, and shared logs.
